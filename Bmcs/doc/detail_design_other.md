## 3. アップデート情報 (G140)

いつ、どんな機能が追加・改善されたかを利用者が確認できるページ（2026-09-26 追加）。
トップページの「お知らせ」は管理者が1件を上書きする形のため、履歴は残らない。一時的な連絡（メンテナンスの予告など）はお知らせ、機能の追加・改善はアップデート情報に書く。

### 3.1 画面レイアウト
- `/Updates`：年ごとに見出しを付け、日付・区分（新機能／改善／お知らせ）・見出し・内容（箇条書き）を新しい順に表示する
- トップページ（`/Top`）：お知らせの下に最新3件（日付・区分・見出し）と「すべて見る」を表示する
- フッターにリンクを置く
- 検索エンジンに登録する（サイトマップにも載せる。`lastmod` は最新の日付）

### 3.2 データ
- **DB には保存しない**。`Data/UpdateHistoryList.cs` にコードとして書く（モデルは `Models/UpdateHistory.cs`）
  - 理由：アップデート情報は機能をデプロイするときに書くもので、コードと同じコミットに入れれば書き忘れにくく、履歴も git に残る。
    DB にすると、テーブルの追加（移行SQL）と管理者用の編集画面が必要になる
- 日付がはっきりしない古い記録は `IsMonthOnly` で年月までの表示にする（サービス開始の 2021年11月）

### 3.3 追加のしかた（運用ルール）
- **利用者から見える変更をデプロイするときは、同じコミットで `UpdateHistoryList` の先頭に追加する**
- 書くもの：新機能、画面や操作の改善、規約・ポリシーの改定、URL の変更など
- 書かないもの：運営側で見つけて直した不具合、内部の改修（基盤の更新・リファクタリング・計測の追加など）
- 利用者の言葉で書く。画面名・ボタン名は画面の表記に合わせ、技術用語は使わない
- 同じ時期の細かい変更は1件にまとめる（例：2026年9月の全画面のデザイン変更）
