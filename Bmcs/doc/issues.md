**D-9 の検討事項**
- 仮登録の間に何ができるか：本登録までログインさせないと、登録直後の離脱が増えるおそれがある（離脱分析では1日で離脱が118チーム）。
  「ログインや入力はでき、未確認の間は画面に案内を出す」形も含めて判断する
- トークンは `ResetToken` と同様に、ハッシュ化して保存し、有効期限を設け、1回で失効させる。再送には既存の送信回数制限（`SendMailLimitCount`）を使う
- 仮登録のまま期限が切れたアカウントの扱い（ユーザIDを解放するか）
- 既存ユーザ（メール未登録が約45%、登録済みも未確認）の扱い：ログイン時に確認を促すか
- チームのメールアドレス（チームパスワードの再設定に使用）も同じく未確認のため、同様の確認を行うか
- メールアドレス変更時（ユーザ情報編集）にも確認を行う

## 2. 画面の移行

### 2.1 未移行の画面
移行順は、メッセージ → チーム（作成以外）→ ユーザ情報 → アカウント復旧 → 管理系。移行が終わったら Bootstrap と `site.css` を削除する。

| 画面 | 移行時にあわせて対応すること |
| --- | --- |
| メッセージ（3画面） | 入力エラー時にヘルプが消える（`Message/Index`）。非公開チームは他チームとやり取りできない旨の表示 |
| チーム（一覧・詳細・編集・削除ほか） | 入力エラー時にヘルプが消える（`Team/Edit`）。公開チーム一覧の「戻る」がトップへ戻る |
| ユーザ情報（`UserAccount/Edit`） | 入力エラー時にヘルプが消える。**チーム参加がプルダウン（公開チームのみ）で、非公開チームに参加し直せない**。新規登録と同じくチームIDとチームパスワードの入力にする |
| アカウント復旧（6画面） | — |
| 管理系（6画面） | — |

### 見送りではなく「そうしない」と決めたこと
| 内容 | 理由 |
| --- | --- |
| 「確定」ボタンを無くし、試合終了で成績に集計する | 確定は仕様として残し、画面に注意書きを入れる方針（ui 8.1） |
| スコアの入力方式の既定値を「試合結果のみ」にする | 「プレー毎」を既定のまま、説明を改善する。プレー毎は今後改善していく（ui 7.5） |
| 打者結果の既定値を「アウト」にする | 打球方向の既定値「無」と辻褄が合わない。何も選ばずに押せる結果は三振しかない（ui 7.10） |
