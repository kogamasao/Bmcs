# 詳細設計書 - アンケート

## 0. 目的と方針

利用者の要望を把握するための機能。**1回限りの作り込みにせず、設問を差し替えて何度でも実施できる**構成とする。

- 回答は**選択式を中心**とし、文字入力は任意項目のみとする（回答率を上げるため）
- 設問・選択肢はDBに保持する。**設問の登録・変更は移行SQLで行う**（管理画面からの設問作成は未実装）
- ログイン後、未回答のアンケートがある場合のみ回答画面へ誘導する。**回答済みの場合は二度と表示しない**

## 1. アンケート回答 (G130)

### 1.1 画面レイアウト
設問の内容はDBから動的に生成する。

| 項目 | 表示 | 備考 |
| --- | --- | --- |
| タイトル・説明 | Survey.SurveyTitle / SurveyDetail | 説明文は改行を保持して表示 |
| 設問 | SurveyQuestion.QuestionText | 必須／任意のバッジを表示 |
| 補足説明 | SurveyQuestion.QuestionNote | 設問の下に小さく表示 |
| 選択肢（単一選択） | ラジオボタン | AnswerTypeClass = 1 |
| 選択肢（複数選択） | チェックボックス | AnswerTypeClass = 2 |
| 自由記述 | テキストエリア | AnswerTypeClass = 3 |
| 「その他」の入力欄 | テキストボックス | SurveyChoice.FreeTextFLG = true の選択肢を選んだときのみ表示（`wwwroot/js/survey.js`） |
| 回答するボタン | - | |
| あとで回答するボタン | - | ハンドラ `Skip` |

### 1.2 処理ロジック

**初期表示 (`OnGetAsync`)**
1. 未ログインの場合はログイン画面へ。
2. 回答対象のアンケートを決定する（下記「対象の決定」）。対象が無い場合はトップページへ。
3. 設問と選択肢を表示順に取得して描画する。

**対象の決定**
- `StatusClass = 公開中` かつ `DeleteFLG = false`
- 開始日時・終了日時の範囲内（未設定の場合は制限なし）
- ログインユーザが**未回答**（SurveyAnswer に (SurveyID, UserAccountID) が無い）
- 複数該当する場合は SurveyID の小さいものを1件表示する

**回答登録 (`OnPostAsync`)**
1. 対象のアンケートを再取得する（POST値のSurveyIDを信用しない）。
2. 入力値を設問の並びに合わせて整える（`NormalizeAnswerInputList`）。
    - 送信された添字が欠けていたり飛んでいたりしても、再表示で例外にならないようにする
      （運営が設問を追加した直後に送信された場合など）
    - **同じ選択肢を複数回送信されても1件として扱う**（集計の水増し対策）
3. 入力チェック
    - **設問に紐づかない選択肢は未選択として扱う**（改ざん対策。検証と保存で判定をそろえる）
    - 必須設問が未選択・未入力でないか
    - 複数選択の選択数が `MaxSelectCount` を超えていないか
    - 自由記述が文字数上限を超えていないか
4. SurveyAnswer を作成（**回答時点のチームID**をセッションから保存する）。
5. 設問ごとに SurveyAnswerDetail を作成する。
    - 単一選択：選択肢1件／複数選択：選択された数だけ作成／自由記述：AnswerText に保存
    - 「その他」（FreeTextFLG = true）を選んだ場合のみ、自由入力を AnswerText に保存する
6. 保存に失敗した場合の扱い
    - **ユニーク制約違反（二重送信）のみ**完了扱いとする
    - それ以外（DB障害など）はエラーを表示する（保存されていないのに完了と表示しないため）

**入力エラー時の再表示**
- 選択状態と自由記述を復元する（`IsSelected` / `GetFreeText` で**設問IDから引き当てる**）
- 選択上限のある設問では、残り選択数を表示し、上限に達したら他の選択肢を選べないようにする（`survey.js`）

**あとで回答する (`OnPostSkip`)**
- セッションに保留フラグ（`SessionConstant.SurveySkip`）を設定し、トップページへ遷移する。
- **このセッション中はログイン時の誘導を行わない。次回ログイン時には再び表示する。**
- URLを直接開いた場合は回答できる（保留後も回答可能）。

### 1.3 ログイン後の誘導
`Pages/Index.cshtml.cs`（ログイン処理）にて、以下をすべて満たす場合に `/Survey/Answer` へ遷移する。

- 管理者でない
- セッションに保留フラグが無い（ログアウト時に解除される）
- **ログイン前にアクセスしていたページ（UrlAfterLogin）が無い**
  ※ディープリンクからの復帰を妨げないため
- 回答受付中かつ未回答のアンケートがある

判定中に例外が発生した場合（アンケート用テーブルが未作成の場合など）は、
**ログインを止めずに誘導のみ行わない**（ログには出力する）。

## 2. アンケート集計 (G131 - 管理者用)

**導線**：ヘッダーメニュー「アンケート集計」（管理者でログインした場合のみ表示）

### 2.1 画面レイアウト
| 項目 | 内容 |
| --- | --- |
| アンケート選択 | プルダウン（削除以外の全件）。同名を区別できるようIDを併記 |
| カテゴリ絞り込み | チームカテゴリ（小学生〜プロ、全て） |
| 回答で絞り込み | **単一選択かつ選択肢10個以下の設問の選択肢**。「代表が選んだ機能」のように属性別の傾向を見る |
| 回答者数 | 絞り込み後の件数。絞り込み時は絞り込み前の件数も表示 |
| 回答チーム数 | 1チームから複数人が回答した場合の偏りに気づくため |
| 回答率 | 有効ユーザ数に対する回答者数の割合 |
| 設問ごとの分母 | 「この設問への回答：n名／無回答：n名」 |
| 選択肢ごとの集計 | 件数・割合・横棒グラフ |
| 「その他」の入力内容 | 該当の選択肢の下に、回答者の属性付きで一覧表示 |
| 自由記述 | 回答内容を、回答者の属性付きで一覧表示 |

**回答者の属性**：`チーム名 / カテゴリ / 試合登録数`
同じ意見でも、年100試合のチームか年数試合のチームかで重みが異なるため、判断材料として添える。
試合登録数は Game テーブルから算出するため、回答者に追加の質問をする必要がない。

### 2.2 処理ロジック
1. **管理者以外は404**とする。
2. 対象アンケートの回答を取得し、次の条件で絞り込む。
    - カテゴリ：その種別のチームに属する回答のみ（SurveyAnswer.TeamID＝**回答時点のチーム**を使用）
      ※チーム未所属ユーザの回答は、カテゴリ指定時には含まれない（画面に注記を表示する）
    - 回答内容：指定した選択肢を選んだ回答のみ
3. 設問ごとに、選択肢別の件数と割合を算出する。
    - **割合の分母は「その設問に回答した人数」**とする（任意設問は無回答がいるため、全回答者数を分母にすると実際より低く見える）
    - 複数選択の設問には「合計は100%を超える」旨を表示する
4. 表示順は、**単一選択は選択肢の順**（順序に意味があるため）、**複数選択は件数の多い順**とする。

### 2.3 絞り込み条件の自動生成
「回答で絞り込み」の候補は、設問の定義から自動で作成する（単一選択かつ選択肢が10個以下）。
そのため、**次回以降のアンケートでも設定を追加することなく、属性別の集計ができる**。

## 3. 運用手順

```sql
-- 1) 移行SQLを実行する（アンケートは「下書き」で作成される）
-- 2) 内容を確認する
SELECT q.DisplayOrder, q.QuestionText, c.DisplayOrder, c.ChoiceText
  FROM dbo.SurveyQuestion q
  LEFT JOIN dbo.SurveyChoice c ON q.SurveyQuestionID = c.SurveyQuestionID
 ORDER BY q.DisplayOrder, c.DisplayOrder;

-- 3) 公開する
UPDATE dbo.Survey SET StatusClass = 2, UpdateUserID = N'ADMIN', UpdateDatetime = SYSDATETIME() WHERE SurveyID = <ID>;

-- 4) 終了する
UPDATE dbo.Survey SET StatusClass = 3, UpdateUserID = N'ADMIN', UpdateDatetime = SYSDATETIME() WHERE SurveyID = <ID>;
```

**次回のアンケートを実施する場合**は、同じ形式で Survey / SurveyQuestion / SurveyChoice を追加するSQLを作成する。
前回のアンケートを「終了」にしておけば、回答済みのユーザにも新しいアンケートが表示される。

## 4. 制約事項
- 管理画面からの設問の作成・編集は未実装（移行SQLで行う）
- 回答の修正・取り消しはできない
- 未ログインでは回答できない（重複回答を判別できないため）
- 回答のCSV出力は未実装
- 自由記述は1000文字まで（`SystemConstant.SurveyFreeTextMaxLength`）
- **移行SQLはアプリのデプロイ「前」に実行する**
  テーブルが無い状態でも例外を捕捉してログインは通すが、毎回エラーログが出る

## 5. 本機能で取得できないこと（重要）
本機能はログイン後に表示するため、**回答するのは「いま使い続けているユーザ」に限られる**。
試合を登録した後すぐに離脱したチームからは、永久に回答が得られない（生存者バイアス）。

「なぜ離脱したか」を知るには、**離脱したチームの登録メールアドレス宛に別途アンケートを送る**必要がある。
本機能の結果は「**残っている人に何を足すか**」の判断材料であり、離脱率の改善には直接つながらない点に注意する。
