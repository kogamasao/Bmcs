# 詳細設計書 - メンバー管理

## 1. メンバー一覧 (G020)

### 1.1 画面レイアウト
| 項目名 | 物理名 | 表示内容 | 備考 |
| --- | --- | --- | --- |
| 背番号 | Member.UniformNumber | Text | |
| 名前 | Member.MemberName | Text | |
| メンバー区分 | Member.MemberClassName | Text | 選手、監督、コーチなど |
| 投 | Member.ThrowClassName | Text | 右投、左投 |
| 打 | Member.BatClassName | Text | 右打、左打 |
| ポジション | Member.PositionGroupClassName | Text | 投手、捕手、内野手、外野手 |
| メッセージ | Member.MessageDetail | Text | |
| 操作 | - | Button | 編集、詳細、削除（権限による） |

### 1.2 処理ロジック
1.  **データ取得**:
    - `teamID` パラメータで指定されたチームのメンバーを取得。
    - 削除フラグ (`DeleteFLG`) が false のレコードのみ。
    - 公開フラグ (`PublicFLG`) が true または自分のチームの場合のみ表示。
2.  **ソート順**:
    - メンバー区分 > ポジション > 背番号 の順で昇順。
3.  **ページネーション**:
    - 1ページあたり20件表示。
4.  **権限制御**:
    - 自分のチームまたは管理者の場合のみ、追加・編集・削除ボタンを表示。

## 2. メンバー登録 (G022)

**2026-09-26 に、複数人をまとめて登録する画面に変更した**（issues.md D-1・D-2）。
以前は1人ずつ登録し、登録のたびにメンバー一覧へ戻っていた（1人7項目×14人で42回のページ遷移）。

### 2.1 画面レイアウト
1行に1人ずつ入力する。PC では1行に並べ、スマートフォンでは「背番号・名前・削除」と「区分・投・打・ポジション」の2段にする。

| 項目名 | 物理名 | 型 | 必須 | 制約・備考 |
| --- | --- | --- | --- | --- |
| 背番号 | MemberRowList[i].UniformNumber | Text | No | 数字3桁以内。全角数字は半角に変換して保存する |
| 名前 | MemberRowList[i].MemberName | Text | Yes（入力した行のみ） | 50文字以内。前後の空白は取り除く |
| メンバー区分 | MemberRowList[i].MemberClass | Select | No | 既定は「選手」（初回の打順自動割当の対象にするため） |
| 投 | MemberRowList[i].ThrowClass | Select | No | |
| 打 | MemberRowList[i].BatClass | Select | No | |
| ポジション | MemberRowList[i].PositionGroupClass | Select | No | |

- メッセージは登録画面から外した（登録後に編集画面で入力する）。全員分の紹介文をこの画面で書くことは少なく、行が重くなるため
- 最初は5行。チーム作成の直後（`?created=true`）は10行で、「チームを作成しました」を表示する（issues.md M-7）
- 「＋5人分の行を追加」で行を増やす（1回に50人まで）。各行の「×」で削除できる
- 名前も背番号も空の行は登録しない（区分などの選択肢だけの行も空とみなす）
- 登録ボタンに、入力済みの人数を「◯人を登録する」と表示する
- 入力中に Enter を押しても送信せず、次の入力欄へ移る（途中までの入力が登録されるのを防ぐ）。日本語入力の変換を確定する Enter では移らない（Safari は `keyCode` 229 で判定）。送信後はボタンを無効にし、二重登録を防ぐ
- スマートフォンでは各項目の見出し（名前は必須の「*」付き）を入力欄の上に表示する。エラーの入力欄には `aria-invalid` と `aria-describedby` を付ける
- 登録後の「◯人のメンバーを登録しました」は、自チーム（と管理者）の一覧にのみ表示する

**行の番号**：行を削除すると番号が欠けるため、`MemberRowList.Index`（hidden）で各行の番号を送る。
追加する行は `<template>` のひな形（番号が `__index__`）を複製して、未使用の番号に置き換える（`wwwroot/js/member-create.js`）。

### 2.2 処理ロジック
1.  **権限チェック**:
    - ログイン済みであること。
    - 自分のチームまたは管理者であること（入力エラーの再表示より先に確認する）。
2.  **入力チェック**:
    - 空の行は登録しないため、行ごとの必須チェックは属性ではなくページモデルで行う。
    - 送信された行の番号（欠番あり）と、再表示する行の番号（0からの連番）がずれるため、`ModelState` をいったん消してから、再表示する行の番号でエラーを付け直す。
    - 名前が1人も入力されていない場合、51人以上の場合はエラー。
3.  **データ保存**:
    - 入力した行を `Members` テーブルに INSERT（1回の保存でまとめて登録する）。
    - `Teams` テーブルの `TeamNumber` (チーム人数) を更新 (+登録した人数)。
4.  **画面遷移**:
    - メンバー一覧画面 (`/Member/Index?registered=登録した人数`) へリダイレクトし、「◯人のメンバーを登録しました」と、次にやること（試合の登録）を表示する（issues.md D-2）。

**背番号の入力チェック**：`Member.UniformNumber` は並べ替え（`OrderUniformNumber`）で数値として扱うが、以前は入力チェックが無く、
数字以外が登録されるとメンバー一覧などで例外になる作りだった。次のとおりにした（登録・編集とも）。
- 全角数字を半角に、前後の空白を取り除いてから（`ToHalfWidthDigits`）、半角数字3桁以内かを確認する（`Member.IsValidUniformNumber`）
- 入力チェックはモデルの属性ではなく各画面で行う。属性にすると、全角・空白を直す前に確認されてエラーになり、
  また入力チェックを追加する前に登録された数字以外の背番号（例「10a」）のメンバーが、名前などだけを直したいときにも保存できなくなるため
- 編集画面では、背番号を**変えていなければ**数字以外のままでも保存できる（変えた場合は入力チェックする）
- 並べ替えでは、全角数字も数値として扱う。数字以外の背番号は例外にせず末尾に並べる
- 既存データの確認は `doc/query/20260926_uniform_number_check.sql`、全角・空白の修正は `doc/migration/20260926_uniform_number_halfwidth.sql`

**改ざんされた送信への対応**：行の番号（`MemberRowList.Index`）が重複している場合は 400 を返す（同じ行が二重に登録されるのを防ぐ）。
管理者が存在しないチームIDを送った場合は 404。区分・投・打などに範囲外の値を送られた場合は、値を結び付けられず空（区分は既定の選手）で登録される（DB に不正な値は入らない）。

## 3. 公開範囲（選手名・代表者名の表示。2026-09-26）

公開チームでも、選手の氏名や代表者名を他チーム・ログインしていない人に見せない選択をできるようにした（issues.md P-12）。
以前は「成績・メンバー（氏名）・代表者名まで誰でも見られる」か「非公開」かの二択で、氏名を出したくないチームは非公開を選ぶしかなかった。

### 3.1 設定（チーム作成・チーム情報変更。部分ビュー `Pages/Team/_PublicSettings.cshtml`）
| 項目 | 物理名 | 選択肢 | 既定 |
| --- | --- | --- | --- |
| 選手名 | Team.MemberNameHiddenFLG | 氏名を表示する（false）／背番号で表示する（true） | 氏名を表示する |
| 代表者名 | Team.RepresentativeNameHiddenFLG | 表示する（false）／表示しない（true） | 表示する |

- 既定は、どちらも表示する（公開する）。非公開にするかどうかは利用者に任せる（ユーザ判断 2026-09-26）
- 「チームを公開する」がオフのときは、「公開する範囲」を薄く表示する（値は保持して送信する）
- チーム作成の「チームを公開する」は既定でオンにした（以前は既定でオフだった）
- 列は起動時に `DbInitializer` が追加する（`doc/migration/20260926_team_public_range.sql` と同じ内容）。既存のチームは 0（今までと同じ見え方）

### 3.2 表示の判定（`PageModelBase`）
- `MemberDisplayName(member)`：選手名を背番号で表示するチームの選手を、**他チーム・未ログインの人**が見る場合は `Member.UniformNumberLabel`（「背番号10」。背番号が無い場合は「選手」）、それ以外は氏名
- `IsMemberNameHidden(member)`／`IsMemberNameHiddenTeam(teamID)`：上の判定（選手単位／チーム単位）。
  メンバーのメッセージと、イニング詳細の備考（どちらも氏名が書かれやすい自由記述）も、これが true の場合は表示しない
- チームIDの比較は `TeamIDComparer`（大文字小文字・全角半角・ひらがなカタカナを区別しない）で行う。DB の照合順序と同じ基準にしないと、
  表記の違うチームID（例「ＪＢ」）で保存された選手の氏名が表示されてしまう。表記ゆれの有無は `doc/query/20260926_member_teamid_mismatch_check.sql` で確認する
- チーム紹介（チームが公開のために書く欄）と、メッセージの投稿者名（ユーザ名）はそのまま表示する。設定欄にその旨を書いている
- `CanShowRepresentativeName(team)`：代表者名を表示するか
- 自チームのユーザと管理者には、いつも氏名・代表者名を表示する（`IsMyTeamData`）
- 選手名を背番号で表示するチームの一覧は、リクエストごとに1回だけ DB から取得する（表の行ごとに問い合わせない）

**選手名を画面に出すときは、`MemberName` を直接出さずに `MemberDisplayName` を使う。** 対象：成績（個人成績・ランキング）、試合結果（打撃・投手成績）、イニング詳細の経過、メンバー一覧・メンバー情報。
自チームだけが開ける画面（打順設定・スコア入力・メンバーの編集など）は対象外。
